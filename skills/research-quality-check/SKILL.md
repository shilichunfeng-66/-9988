# 科研项目质量标准校验

## 用途

在文档生成前后进行质量把控,确保输出符合学校格式规范、内容完整性要求、学生身份水准与政策合规性。

## 校验维度

### 0. 信息完整性校验(最高优先级 — 先于一切)

> 在格式和内容校验之前,先确认所有信息字段已正确处理。

读取学校 format.md 的"信息分类矩阵",逐类核对:

**❓ 未知·必须索取 字段核对**:
```
✓/✗ 推荐学院          → 已填写 / [待填写:未索取]
✓/✗ 项目名称          → 已填写 / [待填写:未索取]
✓/✗ 项目负责人        → 已填写 / [待填写:未索取]
✓/✗ 负责人联系电话    → 已填写 / [待填写:未索取]
✓/✗ 指导教师姓名      → 已填写 / [待填写:未索取]
✓/✗ 团队成员(每人6字段) → 已填写 / [待填写:未索取]
✓/✗ 指导教师信息      → 已填写 / [待填写:未索取]
✓/✗ 申报日期          → 已填写 / [待填写:未索取]
...
```

**检查规则**:
- 任何 ❓ 字段出现编造内容(如自动生成的假姓名/假电话)→ ❌ 严重违规,立即删除并标注 `[待填写]`
- 任何 ❓ 字段仍为空且未向用户索取 → ⚠️ 提示"以下字段尚未向用户索取: {列表}"
- 任何 ✅ 字段为空或仅有占位符 → ⚠️ 提示"以下内容尚未生成: {列表}"
- 任何 🔶 字段未确认 → ⚠️ 提示"以下内容需用户确认: {列表}"

输出信息完整性报告:
```
📋 信息完整性报告
═══════════════════════════
❓ 必须索取字段: 15项
   ✓ 已获取: 12项
   ✗ 未索取: 3项 → [列出,提示补充]

✅ 自动生成字段: 12项
   ✓ 已生成: 12项
   ✗ 未生成: 0项

🔶 需确认字段: 3项
   ✓ 已确认: 2项
   ✗ 未确认: 1项 → [列出,提示确认]

⁉️ 可选字段: 4项
   ✓ 已提供: 2项
   - 待补充: 2项 → [标注[待补充]]
═══════════════════════════
```

> 若有 ❓ 字段未索取或 ✅ 字段未生成,**不得输出最终文档**,先补充完整。

### 1. 必须保留点校验(格式维度)

读取学校 format.md 中的"必须保留点"清单,逐项核对:

```
✓/✗ 封面"项目编号"字段
✓/✗ 封面学校名称
✓/✗ 封面项目类型全称
✓/✗ 项目类别勾选框(如适用)
✓/✗ 申请人团队信息表
✓/✗ 指导教师信息表
✓/✗ 各章节签字栏
✓/✗ 文中配图标注
✓/✗ 页眉页脚(如要求)
```

发现 ✗ 项,立即补充。

### 2. 必须生成点校验(内容维度)

读取学校 format.md 中的"必须生成点"清单,逐项核对:

```
✓/✗ 项目简介/摘要
✓/✗ 研究实施目的
✓/✗ 研究实施意义(创新点)
✓/✗ 项目研究内容(分点)
✓/✗ 拟解决的关键问题
✓/✗ 相关研究积累与基础
✓/✗ 研究目标(可度量)
✓/✗ 技术路线(含流程图说明)
✓/✗ 创新点(2-3个,有支撑)
✓/✗ 预期成果(量化)
✓/✗ 进度安排(里程碑表)
✓/✗ 经费预算(明细表)
```

发现 ✗ 项,立即补充。

### 2.5 科研范式要素校验(2026-08-18 新增)

> 依据 orchestrator「步骤 2.6 项目思考环节」判定的科研范式,校验正文是否包含该范式的必加方法论要素。范式定义见 `reference-db/research-paradigms.md`。

| 范式 | 必查要素 | 缺失判定 |
|------|---------|---------|
| ①调查/实证类 | 调研类型、样本设计、调研方法、变量指标、数据分析方法 | 缺任一项 → 🔴 Major |
| ②实验/技术类 | 实验设计、材料与方法、性能指标、对照验证 | 缺任一项 → 🔴 Major |
| ③设计/工程类 | 需求分析、系统架构、技术路线、方案论证 | 缺任一项 → 🔴 Major |
| ④政策/文献类 | 政策/文献库、文本分析方法、演进脉络 | 缺任一项 → 🔴 Major |
| ⑤纯理论类 | 理论框架、假设命题、推导逻辑、边界条件 | 缺任一项 → 🔴 Major |

**统计合理性审查(实验/技术类,借鉴 nature-statistics)**:
- 数值是否有来源或限定语(拟/预期/争取达到)? 无来源又无限定语 → 🔴 涉嫌编造
- 性能目标预估是否有文献支撑? 无文献支撑 → 🟡 建议删除或标注"探索性目标"
- 单位/精度是否统一? 混乱 → 🟡 修正

**问题分级(借鉴 nature-reviewer,全文校验统一采用)**:
- 🔴 **Major**(重大问题): 内容缺失 / 逻辑矛盾 / 涉嫌编造 → **必须返修**
- 🟡 **Minor**(一般问题): 表述不严谨 / 论据不足 / 术语不当 → 建议修正
- 🟢 **Suggestion**(建议): 可优化细节 → 酌情采纳

### 3. 身份匹配校验(学生水准)

核对内容是否符合在读研究生/博士生水准:

| 检查项 | 要求 | 常见问题 |
|--------|------|---------|
| 学术表述 | 规范但不拔高 | ❌ "国际领先""填补空白" |
| 研究视角 | 体现学生探索性 | ❌ 过度商业化/工程化 |
| 创新点 | 实事求是 | ❌ 夸大创新程度 |
| 引用规范 | 标注来源 | ❌ 无引用或引用不规范 |
| 经费预算 | 符合学生项目限制 | ❌ 预算过高或科目不合理 |
| 成果承诺 | 可达性合理 | ❌ 承诺 SCI 一区等过高成果 |
| 团队描述 | 学生视角 | ❌ 模仿教师级别表述 |
| 因果声称 | 教育研究多为相关与解释(2026-08-30 吸收 research-proposal-writer) | ❌ "必然导致""显著提升XX成绩"等过强因果承诺 |

### 4. 政策符合性检查

| 检查项 | 要求 |
|--------|------|
| 经费额度 | 符合项目类型规定(大创 0.5-2万,国家级 20-60万等) |
| 经费科目 | 符合管理办法(大创不列劳务费/大额设备费) |
| 成果形式 | 符合项目要求(论文/专利/实物/报告) |
| 知识产权 | 权属清晰(纵向归单位,横向按合同) |
| 成果标注 | 注明项目资助(如"国家级大学生创新创业训练计划项目资助") |
| 诚信承诺 | 含诚信声明(如要求) |

### 5. 学术规范检查

| 检查项 | 要求 |
|--------|------|
| 引用标注 | 引用他人成果须标注来源 |
| 数据真实 | 实验/调研数据真实可追溯 |
| 参考文献格式 | 统一格式(GB/T 7714 或学校要求) |
| 署名规范 | 学生一作或导师一作学生二作 |
| 无抄袭 | 内容原创,无大段复制 |

### 6. 项目逻辑审核(轻量 — 聚焦核心,不消耗大量 token)

> 对已通过格式和内容校验的文档,进行一次轻量逻辑审核。抽查式验证,不逐字审查。

**审核清单**:

| 维度 | 检查方法 | 判定 |
|------|---------|------|
| ⏱️ 时间信息 | 抽查: 申报日期不晚于起始时间? 完成时间在起始时间之后? 年级(如2024级)与申报年份匹配? 进度节点时间在总周期内? | ✓ 时间逻辑自洽 / ⚠️ 发现矛盾: xxx |
| 🔗 内容自洽 | 抽查: 研究目标是否被后续内容覆盖? 研究方法与预期成果匹配?(如问卷法不能产出实验数据) 各章节之间有无直接矛盾? | ✓ 内容逻辑通顺 / ⚠️ 发现矛盾: xxx |
| 🎯 主题聚焦 | 抽查: 每章开头是否与核心主题相关? 有无大段内容偏离项目主题? 创新点是否确实围绕本项目? | ✓ 全篇围绕核心主题 / ⚠️ 偏题: xxx |
| 📝 核心一致性 | 抽查: 摘要/简介中描述的项目内容与实际正文一致? 关键术语定义是否前后统一(不能前面说A后面说B)? | ✓ 核心描述一致 / ⚠️ 不一致: xxx |

**审核原则**:
- **轻量快速**: 每项抽查 1-2 处关键位置,不做全文通读
- **有疑点才深看**: 只在发现可疑时才深入对应段落
- **修正定位**: 有 ⚠️ 只修正具体问题段落,不触发重写
- Token 预算: 此维度控制在 400-600 token 以内

### 7. 去AI化复查(轻量)

> 在输出前快速扫描,仅标记最明显的 AI 痕迹,就地微调。

| 检查项 | 判定标准 | 处理 |
|--------|---------|------|
| 句式多样性 | 连续3句以上长度相似(<5字差)视为模板句 | 微调其中1句长度或结构 |
| AI 标记词密度 | "系统性""创新性""机制""路径"等词每段不超过2次 | 超标则替换为自然词汇 |
| 万能句式 | "具有重要理论意义和实践价值"等万能句 | 替换为具体表述 |
| 段落工整度 | 连续3段长度差不超过20%视为过于工整 | 可接受,仅做标记 |

> Token 预算: 此维度控制在 300-400 token 以内。

## 校验流程

1. 读取学校 format.md 的必须保留点与必须生成点清单
2. 读取项目类型文件(project-types/{类型}.md)的成果与经费要求
3. 读取通用政策参考(policies/通用/学术规范与经费管理.md)
4. 逐项核对上述 5 个维度
5. 汇总校验结果:

```
📋 质量校验报告
═══════════════════════════
格式保留点: ✓ 8/8 全部通过
内容生成点: ✓ 12/12 全部通过
身份匹配:   ✓ 符合学生水准
政策符合:   ✓ 经费/成果/知识产权合规
学术规范:   ✓ 引用/数据/署名规范
═══════════════════════════
```

6. 若有未通过项,列出具体缺失内容并补充
7. 补充后重新校验,直至全部通过

## 字数校验

核对各章节字数是否在 format.md 规定的区间内:

```
章节             当前字数   要求区间    状态
项目简介         450字      300-500字   ✓
目的意义         2800字     2000-3000字 ✓
研究内容         2200字     2000-3000字 ✓
...
```

字数不足的章节提示扩充;字数超出的提示精简。

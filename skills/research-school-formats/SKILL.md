# 学校格式适配

## 用途

管理学校格式参考库,提供格式查询、应用、校验与新增能力。

## 数据位置

学校格式库位于: `schools/`,按「学校 → 项目类型」分层组织:

```
schools/
├── _index.md              学校索引(名称→目录映射)
├── {学校名}/
│   ├── profile.md         学校画像
│   ├── {项目类型}/        如: 大创 / 教师科研 / 校级...
│   │   ├── 申报书-format.md   申报书格式规范
│   │   ├── 中期报告-format.md 中期报告格式规范
│   │   ├── 结题报告-format.md 结题报告格式规范
│   │   ├── 母版_申报书.docx    母版文件(如该校该类型有专属母版)
│   │   ├── generate.py        生成脚本
│   │   └── format_apply.py    格式处理脚本
│   └── policies.md        校级政策(可选)
```

## 核心能力

### 1. 格式查询

接收学校名称,返回该校的格式规范:

1. 读取 `schools/_index.md`,查找学校(支持别名匹配)
2. 若找到,读取对应的 `{文档类型}-format.md`
3. 返回: 默认字体字号、章节结构、必填字段、必须保留点、必须生成点、页面设置

### 2. 格式应用

将生成内容套入学校格式:
- 按 format.md 的章节结构组织内容
- 应用默认字体字号(正文/标题/表格/页面)
- 填充必填字段(封面信息/团队表/指导教师表)
- 保留必须保留点(签字栏/固定表格/页眉页脚)
- 应用章节编号规则(中文数字/混合编号/阿拉伯数字)

**分点段落加粗规则(2026-08-18 固化,含实现铁律)**:
- 分点段落("1. 小标题:描述"或"(1) 小标题:描述")只加粗**编号+小标题+冒号**部分,冒号后的描述不加粗
- **实现铁律**: 判断段落类型时,含冒号的分点段落(`subhead`, 正则 `^\d+[\.、]\s*\S+[：:]`)**必须先于**三级标题(`h3`, 正则 `^[1-9][\.、]`)判断。否则"1.项目资金支持:"会被误判为 h3 导致整段加粗
- **项目名称填写位置随学校不同**(见下方「已入库学校」表),套母版时按学校锁定,不可套错

**组装脚本覆盖教训(2026-08-18 固化)**:
- 生成脚本若以「复制母版」开头,每次运行都会**覆盖**之前对该输出文件的手动修改(如手动填的项目名称)
- 因此「项目名称」等应自动填写的字段,必须**固化进生成脚本本身**(脚本内定义字段值 + 末尾自动写入),而不是生成后手动补

### 3. 格式校验

生成文档后,逐项核对 format.md 中的:
- **必须保留点 checklist**: 签字栏/封面要素/固定表格等格式硬约束
- **必须生成点 checklist**: 核心内容章节是否齐全
- **必填字段**: 封面与信息表字段是否完整
- **字数要求**: 各章节字数是否在区间内

发现缺失项列出清单,提示补充。

### 4. 新增学校

当用户需要添加新学校格式时:

1. 询问用户提供该校的一份已有文档(申报书/报告文件)
2. 分析文件提取: 字体/字号/章节结构/封面格式/编号方式
3. 向用户确认默认字体字号(正文/标题/表格/页面)
4. 在 `schools/` 下创建学校目录
5. 编写 `profile.md`(学校画像)
6. 编写 `{文档类型}-format.md`(按 _index.md 中的字段规范)
7. 在 `_index.md` 中注册学校名称与目录映射
8. 无需修改任何 skill 文件

### 5. 未匹配学校处理

若学校不在索引中:
1. 提示用户:"当前学校暂未入库,将使用通用模板(reference-db/通用模板/)"
2. 引导用户:"如需添加该校格式,请提供一份该校的申报书/报告文件,我将分析并建立格式规范。"
3. 使用通用模板生成,但提示格式可能不完全匹配
4. **底板确认(2026-08-29 新增)**: "其他"类型或未入库学校提供的文件,按 orchestrator「通用模板处理规则·第三步 底板确认流程」执行——先问用户文件是否可直接用作底层魔板;能直接用则直接用,不能直接用则解读文件框架 → 问用户哪些部分保留 → 多轮格式校验 → 锁定执行魔板后再生成

## format.md 字段说明

每个格式文件包含以下字段(详见 `schools/_index.md` 中的规范):
1. 学校基本信息
2. 默认字体字号(正文/标题/表格/页面)
3. 文档章节结构(必填/选填标注)
4. **信息分类矩阵(核心)** — 每个字段/章节必须归入四类:
   - ✅ 已知·自动生成: 基于项目主题可推导 → 直接生成
   - 🔶 已知·需确认: 系统生成建议 → 用户确认
   - ❓ 未知·必须索取: 仅用户知道的个人信息 → 按格式询问后填写
   - ⁉️ 未知·可选: 用户可能有 → 询问一次,可留空
5. 必须保留点(格式硬约束)
6. 必须生成点(内容硬约束)
7. 字数与表述要求
8. 页面设置
9. 特殊注意事项

> 新建学校 format.md 时,**必须**完成信息分类矩阵,不可省略。未分类的字段在生成时会导致遗漏或编造。

## 翻译-审稿修正循环（A/B/C 三级修正法 — 2026-08-30 新增）

> 适用场景: 用 #1 完成中英翻译、用 #16 模拟审稿后，对审稿发现的问题进行分级修正。标准循环为「翻译 → 双视角审稿 → 分级修正 → 复测」，直至 Critical Weaknesses = 0。

### 问题分级与处理路径

| 类别 | 判定特征 | 处理路径 |
|------|---------|---------|
| **A 类·原文自带缺陷** | 数据不全 / 无引用 / 无统计方法（译文受"不添加原文没有的内容"约束而忠实继承） | **回中文原文补齐 → 重新翻译**，译文不越权替原文做主 |
| **B 类·译文自身缺陷** | AI 味句式 / 直译腔 / 连接词堆砌 | **译文层直接修正**，可调用 humanizer 方法论 |
| **C 类·领域知识型缺陷** | 指标选错 / 设计要素缺失，需领域金标准判断 | **按领域规范替换或补充**（换金标准指标 / 补盲法、安全性、依从率、样本量、基线等设计要素），中英同步修订，**保留被替换项并降级说明**，避免版本断裂 |

### 审稿视角要求

- **单一审稿角色有盲区**，复审时至少切换两个视角：
  - 视角 1 · 方法学审稿人（通用）: 统计报告规范、样本量、偏倚控制、报告完整性
  - 视角 2 · 领域专家（按选题领域切换）: 结果指标是否为该领域金标准、领域特有设计要素是否齐全

### 修正后自检清单

- 数值算术自洽（组内差/组间差/MCID 可验算）
- 中英双语逐项一致（数值、术语、设计要素）
- 新术语按"首次出现标注原文"规则处理
- 历史数值零改动、可追溯（版本演进不断裂）

## 中文论文生成子流程（2026-09-09 新增 · orchestrator 论文线走法）

> 本 skill 同时承担「论文」项目类型的生成走法。当用户要写**中文论文**（非仅英文翻译/润色）时，按以下子流程执行。思考方向详情见 `reference-db/project-types/论文.md`。

### 论文与申报书的本质区别

申报书回答"要做什么、怎么做、为什么值得资助"；论文回答"发现了什么、怎么发现的、有什么意义"。论文以**学术贡献**为核心、以**同行评审通过**为目标。

### 〇 · 三轮研究探讨（默认启用 · 题目/大纲确定后、生成内容前必做）

> **没有大纲？先走「〇-A 论文框架生成」**——产出框架确认单并经用户确认后，再回到本节第二轮。

> 三个板块(大创/教师科研/论文)共有的默认前置环节。**题目确定后、论文结构(大纲)确定后,在正式写论文之前,对研究做三轮自问自答的深度探讨**——把题目吃透、把结构论证闭环、把贡献定位清楚,然后才动笔。三轮不可跳过、不可合并。

**第一轮 · 题目解构(题目确定后触发)** —— 对题目自行追问,抓取题目深度:
1. **核心概念**: 题目的每个关键词,内涵与外延是什么?有没有歧义?
2. **对象与场景**: 研究"谁、在哪、什么现象"?对象范围、数据来源、时间边界清晰吗?
3. **核心问题**: 把题目浓缩成一句可回答的研究问题(疑问句)?
4. **贡献指向**: 题目是否体现核心贡献(新现象/新方法/新结论)?还是泛化的"XX 研究"?

→ 产出: 关键词矩阵 + 一句核心研究问题 + 贡献指向。答不上来 → 回改题目。

**第二轮 · 大纲论证(论文结构确定后触发)** —— 对已定结构(IMRaD 或领域惯例)自行追问,验证论证闭环:
1. **每节论证什么**: 摘要/引言/方法/结果/讨论/结论各自承担什么?有没有重复或越位?
2. **证据链**: 方法→实验/数据→结论的证据链完整吗?有没有跳步?
3. **闭环检查**: 结构能否完整回答第一轮的核心研究问题?
4. **图表规划**: 需要哪些图表?每张图支撑哪个结论?

→ 产出: 论文结构论证 + 图表规划。答不上来 → 回改结构。

**第三轮 · 研究深化(写初稿前触发)** —— 对贡献与边界自行追问,定位独特性:
1. **贡献定位**: 与已有工作相比,贡献是新的还是增量的?层次(新问题/新方法/新数据/新结论)?
2. **创新差异**: 差异点说得出吗?有没有自我拔高?
3. **潜在质疑**: 审稿人可能质疑什么(结论过度声称、数据不足、方法不当)?怎么回应或限定?
4. **结论边界**: 结论在什么条件下成立、什么条件下不适用?边界清晰吗?

→ 产出: 贡献定位 + 质疑应对 + 结论边界。答不上来 → 回补研究设计。

**硬规则**: 三轮全部通过(有肯定结论与依据)才动笔写论文;每轮提问具体、回答有依据(真实文献/数据),不空喊;探讨结论以简表留存(供写作时对照,防漂移);涉及事实/文献/数据遵守反造假铁律。

### 〇-A · 论文框架生成（用户未给结构时必走 · 2026-09-17 补齐）

> 〇 第二轮"大纲论证"只**验证**结构，不**生成**结构——此前生成侧只有一个英文理工大纲模板。本节补齐：先判型 → 套节级模板 → 产出「框架确认单」→ **用户确认后**才进 〇 第二轮论证。用户已自带结构/大纲时跳过本节，直接进第二轮。

#### 1. 类型判定（先判型再搭架，三选一）

| 类型 | 识别特征 | 框架骨架 |
|------|---------|---------|
| **中文社科实证** | 问题导向；问卷/访谈/统计数据；回归或模型检验 | 绪论 → 文献综述与理论基础 → 研究设计（数据·变量·模型）→ 实证结果与分析 → 稳健性与内生性 → 结论与对策建议 |
| **中文理工 / 英文方法类** | 方法或系统创新；实验对比 | 引言 → 相关工作 → 方法 → 实验与结果分析 → 结论与展望（中文期刊常并入末章） |
| **综述型** | 对某领域文献系统梳理，自身无新数据 | 引言（范围与必要性）→ 文献分类框架 → 主题述评（**按主题组织，禁逐篇罗列**）→ 未来方向 → 结论 |

#### 2. 节级模板（每节写什么）

- **引言四步漏斗**：领域重要性（1-2 句）→ 综述收窄（现状与分歧）→ 缺口（**具体到"哪个问题没解决 / 为什么现有方法不行"**，禁泛泛"研究不足"）→ 本文（做什么 + 方法一句话 + 贡献列点 2-4 条）。贡献列点在第一段末或第二段出现。
- **方法节要素清单**：对象与数据（来源/规模/时间窗）→ 设计（变量定义/模型设定/实验设置）→ 实施步骤（**可复现粒度**）→ 工具与版本。铁律：他人可据此复现；统计方法与软件版本写明。
- **结果呈现顺序**：主证据（直接回答研究问题）→ 次要/分组发现 → 稳健性/敏感性。每小节首句＝该小节回答什么；**只报不释**（解释留讨论，与九-2 呼应）。
- **讨论**：按 九-3 四功能展开，不在此重复。
- **结论节**：核心发现回扣研究问题 + 理论/实践意义 + 局限 + 未来方向（四要素可缺不可滥）；**禁复述摘要**。

#### 3. 篇幅配比（全文＝100%，期刊论文口径）

| 类型 | 引言 | 综述 | 方法/研究设计 | 结果与实证 | 讨论 | 结论 |
|------|------|------|--------------|-----------|------|------|
| 社科实证（8000-12000 字） | 10-15% | 15-20% | 15-20% | 30-35% | 并入实证 | 8-12% |
| 理工/方法类 | 8-12% | 10-15% | 25-30% | 30-35% | 10-15% | 5-8% |

- 论证主体（方法＋结果）**合计 ≥55%**；任何单节 ≤35%（防头重脚轻）；
- 学位论文：每节扩为独立章，绪论增研究意义/研究框架/创新点小节，总字数按学位要求另定。

#### 4. 层级编号体系

- **中文期刊/学位论文**：一级 `一、` → 二级 `（一）` → 三级 `1.` → 四级 `（1）`，小标题独立成行（与教师科研线三-C 层级编号同源）；图表 `图1/表1` 全文连续编号；
- **英文论文**：`Section 1 / 1.1 / 1.1.1`；图表按引用顺序；
- 禁混用两套体系；**目标期刊模板另有规定时一律服从期刊**。

#### 5. 框架确认门禁

按判定类型产出「框架确认单」交用户：**类型判定依据 + 各节标题 + 每节写什么一句话 + 篇幅配比 + 图表规划**。用户确认或修改后，方可进 〇 第二轮大纲论证；**未确认不得写作**（与教师科研线二-E 门禁同源）。

### 一 · 题目凝练与贡献定位（动笔前首要）

1. **题目凝练**: 精准界定研究问题,体现核心贡献(新现象/新方法/新结论)；避免"XX 研究"式泛化题目,倾向"具体对象 + 具体问题 + 关键方法/发现"结构；可参考同领域顶刊/顶会命名习惯。
2. **贡献定位**: 明确"解决了什么已有研究没解决的问题"；区分贡献层次(新问题/新方法/新数据/新结论)；用"与已有工作的对比"凸显贡献,不自我拔高。

### 二 · 论证逻辑链与结构规范

1. **证据门控**: 每个事实性声明必须可溯源(引用核验过的文献或自身实验结果)；方法→实验→结论证据链完整不跳步；结论边界清晰(什么条件下成立/不适用)。
2. **结构规范(IMRaD 或领域惯例)**: 摘要/引言/方法/结果/讨论/结论各司其职不重复；图表规范(编号/图注/单位/显著性标注)。
3. **写作规范**: 学术化客观化表述；术语全文统一、数值精度一致；引用规范(GB/T 7714 或目标期刊格式)。

### 四 · 评审视角预审（**Plus 版必做** / 普通版建议，源自 nature-reviewer）

- 以审稿人身份做**三份互盲评审报告**模拟：分别从 ①方法严谨性 ②结果与证据链 ③讨论与贡献定位 三个独立视角各出一份意见，互不通气；
- 每份意见分级 **Major(不改不能投)/ Minor(建议改)**，禁止笼统评价，每条指向具体段落/数据；
- 附加**手稿内部一致性检查**：数值跨章节一致、术语统一、图表编号与文内引用对应、图注与正文结论吻合。

### 五 · 统计审查清单（实证/实验类论文成稿必查，源自 nature-statistics）

八项逐查，缺一即补或如实说明：
1. 实验单位与分析单位是否明确(n 指什么)；
2. 重复数与独立样本是否交代；
3. p 值报告精确值，不用"p<0.05"式含糊；
4. 多重比较是否校正(方法写明)；
5. 是否报告效应量；
6. 是否报告置信区间；
7. 图注是否含统计标注(样本量/检验方法/显著性标记)；
8. 统计数值跨摘要/结果/图注/讨论**四处一致**。

### 六 · 论文精读卡（升级文献卡片法，源自 nature-paper-card）

精读关键文献时，卡片含 10 项：研究问题 / 核心假设 / 方法逻辑 / 数据与样本 / 分析策略 / 主要发现 / **证据链**(哪个结果支撑哪个结论) / **结论边界**(作者承认的适用范围与局限) / 与本研究关联 / 可检验的研究想法。
- 铁律：**他人的"结论边界"就是本研究的切入空间**——引用时不得越界转述(把人家有边界的结论当普适结论用 = 引用漂移)。

### 七 · 数据可用性声明（投稿需要时，源自 nature-data）

- 期刊要求 Data Availability 时,按 FAIR 原则起草声明：数据存放仓储、获取方式、限制原因；
- **反造假联动**：未实际存放的数据不得写"已在 XX 仓储公开"，如实写"available on reasonable request"或据实说明；归属信息由用户提供。

### 八 · 文献实测提醒

- 凡论文含「参考文献」清单或正文 [n] 引用锚点，必须走知网实测检索铁律（见 orchestrator 顶部），逐条核实文献真实存在，禁止凭记忆默写。
- 参考文献格式 GB/T 7714；中文文献优先核心期刊，近三年优先；
- **编号规则**: 文献表编号 = **正文首次引用顺序**(谁先被引用谁排 1)，**中英混排、不按语种分组**；增删文献须整体重排；
- **工具复检**: 出稿必跑 `tools/check_doc.py` —— 字数 / 文献编号正序 / 编号=正文首次引用顺序 / 正文 `[n]` ⊆ 文献表 / 匿名可疑项 / 禁词与 AI 腔；有"问题"时退出码 1，可作生成流程硬门槛。

### 九 · 论文正文写作技法（2026-09-12 新增 · 三线通用技法落地论文）

> 通用总纲见 `reference-db/格式参考/正文写作技法总纲.md`（题目—内容逻辑 / 描述方式 / 思考层数）。本节只写**论文场景的落地要点**。

### 1. 题目与内容的逻辑关系（论文形态）

- **题目构成**：研究问题 + 对象 + 方法/发现指向；避免"XX 研究"式泛化；20-25 字；须与讨论部分的结论呼应；
- **承诺—兑现三查**（成稿必过）：
  1. **承诺词兑现**——题目里的关键词（机制 / 规律 / 关联 / 效应 / 方法）必须在「引言提出的假设」与「结果给出的证据」中兑现；题目写"机制"却只给效果差异 = 机制缺失，改题或补分析；
  2. **层级匹配**——题目尺度 = 研究规模；写成"体系/普遍规律"却只有一组数据 = 层级错配；
  3. **关键词回扣**——引言末、结果小结、讨论段首各回扣题目关键词一次，让读者任何时候都知道"这篇在答什么"。
- **内部一致性检查表**：摘要结论 ↔ 结果数据 ↔ 讨论结论 **三处一致**；图表编号 ↔ 文内引用一致；术语与数值精度全文统一。

### 2. 描述方式（IMRaD 场景映射）

| 技法 | 在论文里怎么用 |
|------|---------------|
| **段落四步法** | 每个正文段落：主题句 → 证据（数据/文献）→ 分析（为什么）→ 与本研究问题或下一段的联结 |
| **述—评—转** | 引言（文献述评）与讨论（与已有工作对比）：述（别人做到哪）→ 评（缺口或不一致）→ 转（本研究如何补） |
| **数据与证据句式** | 结果部分：趋势 + 数值（含精度与统计量）+ 是否支持假设；**结果部分不做讨论**，解释留到 Discussion |
| **理论引用与机制解释** | 引言给机制假设，讨论用因果链解释结果（因为…→ 所以…→ 因此…），与假设前后呼应；引用必须给用途，禁"借鉴了 XX 理论"空转 |
| **边界式表述** | 讨论与结论写"在 A 条件下成立、B 时需谨慎推广"；无边界 = 过度声称 |
| **篇幅节奏** | 方法与结果为主体；引言与讨论收得住；不平均用力 |

### 3. Discussion 论证与情态校准（2026-09-17 nature-skills 上游同步 · PR#209）

> 源自 nature-shared/core/discussion-argument-language.md（上游明确标注"写作指南而非 Nature 官方要求"）。适用于英文与中文论文的讨论部分。

**① 反漏斗方向（方向而非模板）**：引言从领域收窄到本文问题，讨论反向展开——`具体发现 → 综合解释 → 与领域的关系 → 有边界的意义`。展开幅度以证据许可为限，小研究可以、也应该以小的意义收尾。开头锚点三选一：重提未解决的问题（问题解决是主要推进时）/ 重提设计或方法（方法改变可推断范围时）/ 直陈核心发现（发现本身是主要推进时）；**只放一个压缩锚点，不复述引言背景与结果全链**。

**② 四个功能（是功能，不是四段模板；按需合并、调序、省略）**：
| 功能 | 写什么 | 硬规则 |
|------|--------|--------|
| **锚定 Anchor** | 一句有边界的判断陈述核心推进，指出必须合起来理解的若干结果主张 | 最多一个关键数字；禁重放全部效应量/区间/检验 |
| **定位 Position** | 在文献地图上落位：支持/独立证实既有证据、把既有结果延展到新机制人群尺度、限定既有结论的成立条件、与先行研究冲突需要调和、连接此前被分开处理的结果 | 每处文献对比必须说明"与当前主张有什么关系"，禁引用堆砌装饰 |
| **解释与贡献 Interpret/Contribute** | 分三级：**已确立贡献**（设计直接支撑）／**有支撑的解释**（证据偏好但未唯一证明）／**开放推论**（合理的更大后果，需新检验） | 非唯一机制须先列可信竞争解释；创新点显式化，但"首次/ novel"不能替代对实际推进的说明 |
| **划界与延伸 Bound/Extend** | 推断可能在哪里失效、该局限改变什么、什么仍然成立、哪个后续检验能降低不确定性 | 猜想与未来工作与已证明的贡献成比例 |

**③ 结果复述禁令**：结果与讨论可指向同一发现，但句子职能不同——结果句"确立事实"，讨论句"综合出解释"。只重复数字/比较/检验的讨论句**删除**；保留复述仅当读者需要它才能理解随后的综合。

**④ 情态阶梯（选证据许可的最强措辞，不是听起来最强的措辞）**：
| 证据状态 | 措辞 | 准入门槛 |
|----------|------|---------|
| 测试设计内直接确立 | shows / establishes / demonstrates（中文"表明/证实/确立"） | 设计直接检验该命题，且重要的替代解释不支持更弱读法 |
| 有支撑但未唯一确立 | supports / indicates / suggests / is consistent with（"支持/提示/与…一致"） | 仍存在至少一个可信替代解释，或机制系间接推断 |
| 合理解释或外推 | may / might / appears to（"可能/似乎"） | 超出直接检验范围，且明确标记为暂时性 |
| 近必然或排除 | must / cannot（"必然/不可能"） | 仅当逻辑、设计或物理约束真正排除合理替代；应当罕见 |

**情态护栏**：`may not`（可能不）≠ `cannot`（不可能）；`must not` 表禁止而非"不必"（后者用 need not）；禁 `may perhaps suggest` 式**对冲堆叠**（hedging stacking；一个情态或一个校准动词通常足够）；区分**领域建议**（future studies should）与**作者承诺**（we will），不替作者承诺工作；**用 must/demonstrates/因果动词前，必须先说出许可该强度的具体设计特征**，说不出就降一级。

**⑤ 局限 = 声称边界（五步序）**：`受影响的声称 → 未检验或受限的条件 → 对解释的后果 → 什么仍然成立 → 能化解分歧的检验或数据`。单中心样本不是泛泛"一个局限"，它限定的是可推广的人群与场景；说明它威胁的是核心推断还是仅其可迁移性，或都不是。禁用正面结果"化妆抵消"严重局限，也禁把不伤核心结论的边界写成致命伤。

**⑥ 未来工作 = 化解一个不确定性**：每项提议写清——未决问题是什么 / 现有证据为何答不了 / 判别性的实验·数据·分析是什么 / 结果如何改变解释。要一两个关键检验，不要购物清单；禁无科学目的的"扩大样本/更多数据"。

**⑦ 句子功能审计（8 查）**：给讨论部分每句标一个主功能（锚定|综合|定位|解释|贡献|限定|划界|延伸），然后查——反漏斗方向？功能覆盖齐？无结果复放？每处引用比较说明了关系？强动词/情态能过证据审计？每条局限指明了改变哪个声称？每项未来工作化解一个已命名的不确定性？重复功能、对冲堆叠、套话能否删除？

### 4. 思考层数（论文取 L0 / L2 / L4）

- **L0 题目两轮七问**：出题时走（第二轮反证 + 延续性 + 区别性）；第⑦问"能否凝练科学/技术问题"对论文尤为关键；
- **L2 三轮研究探讨**：见本文「〇」节（题目解构 / 大纲论证 / 研究深化）；
- **L4 科研质量三性**：理论性（机制假设有依据）/ 科学性（证据链完整、结论有边界）/ 可实现性（数据可得、样本量能支撑结论）。
- **L1（双轮确认门禁）与 L3（四轮梳理）用于申报书/活页场景，论文不使用**；论文以 **IMRaD 结构规范 + 评审预审** 替代。

> **范围**：本科生毕业论文的**全链条方向**——体例与顺序（含目录、三线表）＋ 降 AI（语体 + 结构）＋ 工具链 ＋ 执行 SOP。
> **依据文件**：`reference-db/格式参考/本科毕业论文体例规范.md`（体例）＋ `reference-db/格式参考/本科生毕业论文文风基准-实测.md`（语体与结构）。
> **实测战绩**：《体医融合视域下大学生体质健康促进的困境与路径研究》测试稿，PaperPure **53.1% → 20 多**（两轮改写），经验全文见 `outputs/降AI率经验总结_本科毕业论文_20260917.md`。

### 11.1 体例与顺序（**动笔前先对锚**）

- **详细规范见 `reference-db/格式参考/本科毕业论文体例规范.md`**，核心五条：
  1. **顺序固定**：目录 → 摘要 → Abstract → 1 绪论 → 2 研究对象与研究方法 → 3 研究结果与分析 → 4 结论与建议 → 参考文献 → 致谢 → 附录Ⅰ/Ⅱ；
  2. **编号用阿拉伯多级** `1 / 1.1 / 1.1.1`（**不是**"一、（一）"），最深三级；
  3. **第 3 章是论文主体**：现状 → 存在的主要问题（x.2.n）→ 优化对策（x.3.n），**问题与对策条目一一对应**；
  4. **必须有目录**：用 **TOC 域**（抓 Heading 1-3）而非手写，摘要/Abstract/正文/参考文献各自另页；
  5. **表格一律三线表**：顶线 1.5pt + 表头下线 0.75pt + 底线 1.5pt，无竖线、无内部横线；表题在表上方（五号加粗居中）、表注在表下方（小五）；表号按正文出现顺序。

### 11.2 降 AI 第一层：语体基准（决定下限）

**原理**：检测器本身也是语言模型，它给每个词算"接下来接哪个词最常见"。AI 写的句子走的是最常见搭配，读起来毫无意外；人写的句子总有几处不常见但说得通。**所以降 AI 不是删禁词、不是改得更规范，而是让句子走出常见套路**——这解释了为什么越工整、越"学术腔"，AI 率越高。

**实测有效的六条**（详见文风基准文件）：
1. **写长句**——句均 ≥65 字，长句（≥60 字）占比 ≥45%；
2. **少用括号与分号**——括号 ≤2 处、分号 ≤2/千字、破折号 0，解释写进句中；
3. **多用顿号并列**（理论推演类 10-12/千字即正常，**不硬凑**）；
4. **关键术语反复使用不换词**（换词是 AI 特征）；
5. **段首常用「本文/本研究」起句**（≈2.5/千字）；
6. **具体信息密集**——用**真实存在**的规范名与机构名（《国家学生体质健康标准》、校医院、体育部），**不编数据**。

**禁用**：聊天式口语（说白了、毛病、管用）；同时**不要追求期刊腔的工整**。

### 11.3 降 AI 第二层：结构对称（决定上限 · 2026-09-17 新发现）

**语体拉平之后仍被标红的段落，几乎全部命中「结构过于对称」。**

| 高风险句式 | 典型写法 | 改法 |
|-----------|---------|------|
| 编号罗列 | 一是…，二是…，三是… | 拆成有主次的叙述，不用序号 |
| 递进排比 | 先靠…再靠…然后…并用… | 合并成一句，或改成因果链 |
| 二元对称 | 理论上…，实践上… | 直接分两句，去掉对举框架 |
| 镜像双句 | X等…，并从A、B、C层面…／Y等**则**… | 两句长短拉开，第二句不"则" |
| 定义式长列举 | 指因…、…、…等原因 | 改成"涵盖几类情况"的叙述句 |
| 分层对称 | 对学校层面而言…对部门层面而言… | 只留主线，其余降为从句 |
| 四字对仗三连 | 识别粗放，干预就…，供给割裂，方案就… | 改成连贯长句 |
| 模板致谢 | 感谢…，感谢…，感谢… | 换成带具体情境的句子 |

- **改法 = 打散对称，不是改词**。
- **行话层（2026-09-18 补充 · 判别力最强的一层）**：AI 写"AI+管理/技术"类题目时，会高频重复同一批圈子术语。实测对照——体育稿（PaperPure 20 多）行话密度 **7.0/千字**（高频词是"体质测试、体育课、校医院"这类常识词）；人力资源×AI 稿原始 **33.4/千字**（流程×31、环节×29、工作流×24、协同×17、决策×16），去行话后降到 **16.0**。硬线：**≤18/千字**（`style_metrics.py` 已内置）。
- **处理办法**：术语只在**首次出现时保留并给平实解释**，后文一律换日常说法——流程→先后顺序/这一段，环节→步骤/这一步，协同→两边怎么配合，决策→系统给出的结论，留痕→把理由存下来，重构→重排，边界→由谁负责；
- **前提是场景化**：把"数据基础薄弱"写成"招聘专员打开后台只看到按学历排的名单，项目经历没有字段可填"，把"流程割裂"写成"面试官手里的评价表对不上系统里的筛选结果"——**有角色、有产物、有系统名，行话自然就少了**；
- **不要用全局词替换**：曾把"逻辑分析法"错换成"道理分析法"、"结构化字段"换成"组成化字段"。必须逐条改、改完 grep 复核。

**话术层（2026-09-18 补充 · 最容易被忽视）**：AI 模仿"人写"时最容易产生**口语表演**——机灵话、金句收尾（"企业买到的是能力""组织跟不跟得上才是""教人怎么点按钮""越早定清越省事"）。这类句子看似有人味，实为 humanizer 过度矫正后的新 AI 腔，检测器同样敏感。修法是**改回平实学术陈述**："人味"来自**具体**，不来自**口语**。`style_metrics.py` 已内置 4 条话术句式（不是…才是 / 的是…缺的是 / 说到底说白了 / 口语表演词）。内容层面同步要求：每段至少落到**字段、节点、步骤、责任人**这一层，停留在"企业应该重视""数据基础薄弱"的概括层即视为空转。
**高风险段落**：综述 / 结论 / 研究对象 / 研究意义 / 致谢（"归纳出来的"天然整齐）；
- **低风险段落**：具体现象描述、有引用落点的问题—对策段（"看到的"天然有细节）。

**第三层（2026-09-18 新增）：具体信息密度——决定真假。**
实测：人力资源稿首版句法、结构全达标，仍被检出高风险，原因是通篇抽象论述——5540 字里**书名号 0 个、数字锚点 1 个**；对照体医融合稿（PaperPure 20 多）有《国家学生体质健康标准》等 4 处书名号 + 5 处数字锚点。
- **硬线：具体锚点（《规范/政策/标准》+ 带单位的数字）≥ 0.8/千字**（`style_metrics.py` 已内置检查）；
- **来源只许四类**：教材/手册、已发表文献（走文献实测）、标准/规范、常规工程取值区间——**不许凭空给精确数**；
- **最好用的来源是已引文献本身**：把文献里的真实样本量、框架维度、结论写进正文（如"基于 887 份企业员工问卷"），一举两得；
- 措辞纪律：仿真/推演数据写"仿真结果显示"，**禁用"实测""试验测得"**；
- **CV 节奏带**：0.50-0.60 正常；<0.45 = 句长过于整齐（全是 60-100 字的长句链），需掺入 10-25 字的短句收尾或转折。

### 11.4 工具链

| 工具 | 用途 | 命令 |
|------|------|------|
| `tools/check_doc.py` | 字数 / 文献编号正序 / 编号=正文顺序 / 锚点⊆文献表 / 匿名 / 禁词 | `python tools/check_doc.py 稿子.docx` |

### 11.5 执行 SOP（照顺序走）

1. **对锚体例**：确认学校/学院的要求；无官方文件则用 11.1 的五条基线。
2. **写内容**：按 11.1 的顺序与章节逻辑写；研究方法按论文类型写实（见 11.6）。
3. **过机器硬线**：`check_doc.py` → 必须 0 问题。
4. **过文风指标**：`style_metrics.py` → 句均/长句/分号/括号达标。
5. **过结构对称扫描**：同一工具输出，**命中越少越好**；命中即按 11.3 表逐条打散。
6. **生成 docx 并刷新目录**：`build_thesis.py` 生成 → 本机 Word 后台 `TablesOfContents.Update()` + `Fields.Update()` → Save → `ExportAsFixedFormat` 出 PDF 自查（页码对不对、表有没有跨页断线）。
7. **再送检**：若仍有标红，**先看标红段落命中哪条对称句式**，对症打散，**不要整篇重写**。

### 11.6 待补：研究方法与数据（用户已提出 · 部分落地）

**已落地**：文献推演型论文的**简版方法章**（`2 研究对象与研究方法`：2.1 研究对象 + 2.2 研究方法 → 2.2.1 文献资料法 / 2.2.2 逻辑分析法），只写实际做过的方法，不虚构问卷与实测。

**待展开**：
1. **方法体系按论文类型切换**——社科调查类（问卷 + 访谈 + 统计）／运动人体科学类（实验或测试 + 指标前后比较）／人文史论类（文献 + 逻辑）；
2. **必须有数据**：正文须有可呈现的数据支撑，结果章要有表或图；
3. **数据可在一定程度上自拟**（用户原话）：不具备实测条件时允许按合理区间构造示例数据。**红线**：构造数据必须在文中标注来源性质（"示例数据 / 模拟数据"），并在交付说明中向用户明示，**不得冒充实测结果**；与反造假铁律的边界须在展开时一并写清。

**展开前置**：等用户给出论文类型、字数、学校要求的完整口径后写入正式流程；未展开前，文献推演型仍按"不补数据"的现行走法。

### 11.7 红线

- 平实不等于口水话——**事实、数据、引用、文献著录一字不动**；必须精确的术语保留，但要带解释；不含虚构内容。
- 具体信息密集用**真实存在**的规范/机构/环节名来撑，**不用虚构数字**。
- 降 AI 改写只动表达，**不动事实与数据**。

# 本科毕业论文体例规范（2026-09-17 建立）

> **来源**：用户本人《芜湖市弋江区中年职场人群智慧体育信息服务现状调查与分析》（池州学院，社会体育指导与管理，2026 届）目录实证 + 《体医融合视域下大学生体质健康促进的困境与路径研究》测试稿落地验证。
> **适用**：本科毕业论文（含体育类毕设）。教师科研申报书、期刊论文另有体例，不套用本文件。
> **配套**：`科研文件/reference-db/格式参考/本科生毕业论文文风基准-实测.md`（语体与降 AI）、`tools/build_thesis.py`（生成）、`tools/style_metrics.py`（自查）、`research-writing` 十一节。
> **优先级**：**学校/学院下发官方格式文件时，一律服从官方文件**；无官方文件时按本规范执行。

## 一、文档顺序（固定，不跳项）

| 序 | 部件 | 页码 | 说明 |
|----|------|------|------|
| — | 封面 | 不编号 | 题目（黑体二号居中）+ 姓名／学号／专业／指导教师（楷体三号居中） |
| — | 目录 | 不编号 | 标题「目　录」黑体三号居中；条目用 **TOC 域**自动生成 |
| 1 | 摘要 | **1** | 中文摘要 200-400 字，3-8 句；关键词 3-5 个，分号分隔 |
| 2 | Abstract | **2** | 英文摘要与中文对应；Key words 与中文关键词对应 |
| 3 | 1 绪论 | 3 | 1.1 研究目的 / 1.2 研究意义 / 1.3 研究现状 / 1.4 概念界定与理论依据 |
| 4 | 2 研究对象与研究方法 | — | 2.1 研究对象；2.2 研究方法（三级列具体方法） |
| 5 | 3 研究结果与分析 | — | **论文主体**，见第三节 |
| 6 | 4 结论与建议 | — | 4.1 研究结论 / 4.2 建议 |
| 7 | 参考文献 | — | 独立另页；编号＝正文首次引用顺序，中英混排 |
| 8 | 致谢 | — | 不用模板化三段式，见文风基准第六节 |
| 9 | 附录Ⅰ / 附录Ⅱ | — | 工具表、问卷、量表等；表号用「附表1／附表2」 |

- **摘要／Abstract／正文／参考文献各自另页**（Word 段落属性"段前分页"），其余按自然流排。
- 封面与目录不计入正文页码；正文页码从 **1** 起。

## 二、层级编号

- **阿拉伯多级**：`1` → `1.1` → `1.1.1`，**最深三级**，不出现 `1.1.1.1`；
- **不使用**"一、（一）""第一章"这类中式编号（除学校另有要求）；
- 三级标题句式：
  - 问题类 → **「问题，表现」**，如"识别粗放，弱势学生缺少分层框架"；
  - 对策类 → **「动作，目标」**，如"建立分层识别工具，把干预对象分清楚"；
- 图表编号：正文用 `表1／图1` 全文连续编号；附录用 `附表1／附图1`，与正文分开计数。

## 三、第 3 章的章节逻辑（本篇的骨架）

```
3 研究结果与分析
  3.1 ×××的现状            ← 先讲清"现在是怎么做的"
  3.2 ×××存在的主要问题     ← 3.2.1 / 3.2.2 / 3.2.3 … 逐条列问题
  3.3 ×××的优化对策        ← 3.3.1 / 3.3.2 / 3.3.3 … 与 3.2 条数相同、顺序对应
```

**硬规则**：**3.2 与 3.3 的条目必须一一对应**（问题 n ↔ 对策 n），建议在 3.3 开头用一张三线表把对应关系列出来，读者一眼能看到"问题—对策"的闭合。这是评审最看重的结构信号。

## 五、目录（必须有）

- **必须是 TOC 域，不是手写**——手写的目录改了正文就失效；
- 生成前提：各级标题必须用 **Heading 1/2/3 样式**（仅靠直接排版设黑体，目录抓不到）；
- 域设置：`TOC \o "1-3" \h \z \u`，并在 `settings.xml` 置 `w:updateFields = true`，Word 打开即自动刷新；
- 若打开后目录显示为提示文字：`Ctrl+A` → `F9` → 更新整个目录；
- **页码校验**：摘要 = 1、Abstract = 2、正文第一章 = 3（与参考稿一致）；
- 目录条目的字号由「目录 1/2/3」样式控制（Word 内部样式名为 `toc 1 / toc 2 / toc 3`，改样式时注意大小写）。

## 六、三线表规范

**论文专用三线表**：只保留三条横线，**无竖线、无内部横线**。

| 线 | 线宽 | 说明 |
|----|------|------|
| 顶线 | 1.5 pt | 表格最上方 |
| 表头下线 | 0.75 pt | 仅表头行下方 |
| 底线 | 1.5 pt | 表格最下方 |

- **表题在表上方**（"表1　表题"），**表注在表下方**（"注：数据来源/说明"）；
- **表号按正文出现顺序**编号，正文必须先有"见表n"再出现表；
- **列宽不均等**：用百分比设列宽（如 16% / 42% / 42%），并固定表格布局，否则长文字会被挤成两行；
- **常见错误**：① 用 Word 默认"网格型"表格（带竖线）；② 表题放在表下方；③ 表跨页断线；④ 表内出现未标注来源的编造数据。

**数据红线**：表中数据必须真实可查；无实测条件时按合理区间构造的**示例数据必须标注"示例数据／模拟数据"**，不得冒充实测结果。

## 七、生成与自查流程

```bash
# 1) 从 md 源生成体例合规 docx（三节 + TOC 域 + 三线表 + 页眉页脚）
python tools/build_thesis.py 源文件.md 输出.docx

# 2) 硬规则检查（字数/文献编号/锚点/匿名/禁词）
python tools/check_doc.py 输出.docx

# 3) 文风与结构自查（正文口径指标 + 结构对称扫描）
python tools/style_metrics.py 输出.docx

# 4) 更新目录页码并导出 PDF 自查（本机 Word，后台不可见）
#    打开文档 → TablesOfContents.Update() → Fields.Update() → Save → ExportAsFixedFormat
```

**交付前必看 PDF**：目录页码对不对、三线表有没有跨页断线、表题表注位置、页眉页脚是否只在正文节出现。
